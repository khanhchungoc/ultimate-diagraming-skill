• Click : Select a table (its header), a column (its row), a line (or its label), an area (its name pill) or a note
  • Hover a Table : Light up the lines that enter it (amber: tables it is the parent of) and leave it (blue: tables it points to) and the joined column rows; everything else dims
  • Hover a Line : Light up the two columns it joins
  • Table (dock) : Add a table after the selected one, in its area, with an id primary key (uuid); its name opens for editing. Or drag the button onto an area to drop it there
  • Double Click, Enter or F2 : Rename the selected table or column, edit a line's label or an area's name. In a column, Tab goes name, then type, then the next row; Enter on the last row adds a column; an empty name and Enter removes it; Esc keeps the old text. Renaming a column renames it in every relationship
  • + Column in a table's action bar : Add a column at the end
  • PK / FK / U / ? in a column's action bar, or P F U ? on a selected row : Toggle primary key, foreign key, unique, nullable
  • Drag a row, or Alt + ↑ / ↓ : Move the column up or down in its table. Deleting a column removes it from the relationships that name it
  • Drag from a column's port (the dot at the right edge of a hovered row, or of the header) onto another table or column : Draw a relationship from the table that holds the key (the child) to the table it points to (the parent). From a column onto a column, the start column becomes a foreign key, the line is dashed (solid when that column is part of the primary key) and the ends are zero-or-many to one (zero-or-one for a nullable column). Onto a table header, no column is named. Onto the same table's key: a self-reference
  • Relationship (dock) : Arm the tool, then drag from any column to another table; Esc cancels
  • Drag a selected line's end handle : Move that end to another table or column
  • Action bar of a line : two rows of crow's-foot buttons (Child end, Parent end: exactly one, zero or one, one or many, zero or many), Identifying (solid or dashed), reverse (swap child and parent) and label
  • Area (dock) : Add a subject area (the first one takes every table). Double-click its name pill to rename it, drag the pill to reorder areas, drag a table into another area to move it there; its action bar has colour swatches and delete (the tables move to the first remaining area; with no area left the diagram has none)
  • Note (dock), N or the + chip on a hovered table : Add a note to the selected table (the dock button waits for a click on a table if none is selected, or drag it onto one). Enter breaks a line; Ctrl + Enter, Esc or a click away finishes; an empty note is dropped. A table with a note has a badge: hover it to peek, click it to edit
  • Drag a note's card : Pin it where you drop it. Drag its link handle onto another table (or Shift + Click a table while the note is selected) to link it, and onto a linked table to unlink it
  • ↑ ↓ / ← → : Walk the columns of a table / the tables
  • Delete : Delete the selection: a table (it asks first when it has relationships, and removes them), a column, a line, an area (it asks first) or a note
  • Esc : Cancel what is under way (a drawing, a drag, an armed tool), then clear the selection
  • Chevron in a table header : Collapse the table to its header, or expand it (also in ?present); the layout re-tidies when Auto-Tidy is on
  • Columns : Cycle what every table shows: all columns, key columns only (with a "+ N more" row), or table names only; saved with the file
  • Types : Show or hide the column types
  • Notes : Show every note on the canvas at once, or hide them
  • Auto-Tidy : On (remembered in this browser), the diagram re-arranges itself after every structural edit and a dropped table only chooses its area. Off, tables stay where you drop them (Drag a table; dashed guides snap it to another table's centre) and only Tidy lays the whole diagram out, once, now
  • Area name : Each subject area is a band with its name pill at the start; the pill stays at the visible edge when you pan past it
  • Reading a line : A crow's foot (three prongs) marks the "many" end, a bar "one", a circle "zero"; a solid line means the key is part of the child's primary key, a dashed one that it is not. Lines leave and enter at the column that holds the key
